# AI Development Workflow

先核对项目工作流、最新用户决定、依赖、风险和独立验证需要，沿用项目已采用的分类、需求及契约机制，按风险取用流程。未设统筹时，短周期、低依赖的单仓小改可由单执行会话直接完成。需要协调时，沿用用户亲自衔接或唯一统筹的既有选择。有统筹时通常逐段协调。项目或任务明确采用负责人串联，且同任务交接路线、接收方、权限和所需资源可核实时，由统筹首派给任务负责人，再按[同任务直接交接](references/direct-handoff.md)执行。已有安排继续有效。

## 组织、派发与收取

- 统筹负责只读查询、协调、派单、任务包、证据核对和验收管理。实质交付由执行者承担。每轮首次修改源码、测试或其他交付物，或运行用于交付或验收的实质测试前，先核对当前会话在该任务中的角色。涉及仓库操作时，同步按[工作区定位](references/coordination.md#执行会话的工作区定位与操作范围)核对已确认的实施分支及归并安排。收到简短确认或实施范围批准后，沿用已确认的分工。轻量修复和同时使用专项实施技能的任务同样适用。当前会话承担统筹时，转入实施、合流、正式文档修订或实质验证前，按[任务包](references/coordination.md#任务包)核对实际执行者、授权及唯一写入负责人，复用覆盖本次的有效派单或按授权下发。采用统筹时，独立文档修订在制作清单、逐项核验或拟稿前完成派发安排，具体见[文档分工](references/coordination.md#文档任务的制作与确认)。
- 已采用统筹的任务，在现有协调记录保留当前会话角色、执行者、唯一写入负责人及本技能和适用引用的入口。续接摘要保留该记录的入口。上下文压缩后，或续接摘要缺少分工依据时，在首次安排实施或实质验证前，重新读取任务适用的技能及引用，从最新协调记录、原派单或可定位的用户决定核实角色、执行者和授权。核实仍为统筹时，按既有分工复用派单或按授权下发。角色或写入归属暂无法核实时，先做只读核查，仅暂缓受影响的写入或实质验证。 已启用插件 Hook 时，按[压缩续接](references/coordination.md#插件的压缩续接)登记或撤销当前统筹任务。Claude Code 当前会话 ID 由宿主替换 `${CLAUDE_SESSION_ID}`，未替换时不得作为 ID 使用。
- 子 Agent 和独立主会话均按实际能力和专业职责匹配。用户已指定时沿用。未指定时，统筹在已有授权内按[执行者选择](references/coordination.md#组织方式与执行者选择)优先复用合适会话；预计需要多轮与用户直接交互的任务，安排用户可直接进入和回复的独立主会话。仅澄清会实质影响执行的缺项。按[工作区定位](references/coordination.md#执行会话的工作区定位与操作范围)核实实际工作区和适用规则，支持经核实的绑定或显式目录，按用户选择安排主工作区或 worktree。
- 派发前核实依赖、执行者占用、实际执行存续、回报与收取入口、检查点和触发方式。启动或接替时从现有协调记录核对轮次出口和收取安排，后续沿用有效约定，有变化才更新。默认下发后交还用户。约定检查点时明确后续触发方式，统筹在被唤起后核查。交还前确需查状态时，只做即时查询。仅当用户明确要求本轮持续跟进，或满足技术保全条件时，才阻塞等待。单说“先完成某项”只指定顺序；用户明确要求持续跟进时，跟进到约定结果并结束。交还时简报已派事项和负责人、待派或暂缓事项，以及谁在何时触发收取。没有自动唤醒能力时说明手动续接。按[轮次出口与续接](references/coordination.md#统筹的轮次出口与续接)处理必要的技术保全等待。缺少执行者、工具或权限时，报告缺口或交用户人工转交任务包。统筹继续履行协调职责，实质交付仍由执行者负责。
- 执行者首次接单前读取本技能、任务适用引用、项目规则及相关技能。复用时核对已加载内容和变化，任务包提供可访问入口。技能或关键引用不可读取时，说明缺项及受影响动作，仅暂缓依赖该资料的操作，其他独立且已授权的工作继续。执行者可直接处理职责内的局部沟通。共性问题、跨任务协调和授权缺口默认由当前唯一顶层统筹收口。执行者再委派须核对授权，原执行者继续负责整体交付。
- 统筹核收阶段交付、确认接替完成或发现退出依赖解除时，主动按[接管与退出](references/handoff.md)核查所辖会话。已达到退出条件、保全和依赖核验通过，且已有覆盖该会话或批次的归档授权时，直接归档并回读实际状态。缺少授权时，在本轮汇总已具备条件的会话、可能影响及缺失授权，可按明确范围一次确认。仍有职责或依赖的会话保留，记录下次核查条件，在后续已约定的核收中重查。

## 基线、授权与验收

- 复用现有记录，保留可定位的任务目标、非目标、版本、实际工作区、负责人、决定来源及覆盖关系、依赖与交付条件、证据和停止点。先定位证据缺口，只补影响判断的最小信息。局部疑问仅暂缓受影响项，统筹按既有分工派发已就绪且获授权的独立事项。推荐或派发方案前核对已确认目标、已核事实及关键反例，排除违反约束的路径。专业方案由对应执行者产出。
- 创建、复用、派单、再委派、消息、分支和 worktree 操作，以及本地开发、提交、推送、合并、部署、配置发布、远程主机变更、直接 DB 写和真实 API 写，分别核对用户授权及工具许可，遵守系统、用户、项目和工具边界。方案批准只覆盖已确认范围。直接复用仍有效且覆盖本次动作的授权。常规实现选择在已确认范围内由执行者处理，无需重复询问。缺少写授权时先说明目标环境、动作和影响，再取得所需授权。
- 收到暂停或撤权即停止受影响的操作安排及下游放行，沿获准链路通知，涉及写入时核查实际停写。发现统筹代做时，停止相关实质操作、保全产物及证据，确认停写后移交唯一写入权。按[状态和回报](references/coordination.md#状态和回报)核查在途操作。复工须符合最新有效决定、操作授权和适用条件。
- 单个开发任务默认由开发者自验，满足任务通过条件后交付。满足项目提测条件并进入需求级测试后，由未参与相关实现的验证者在独立上下文中验收。按[验收与证据](references/verification.md#验收与证据)判断是否提前做专项独立验证。单任务交付、专项验证、需求级独立验收和用户业务接受分别记录，用户完成约定的业务接受。按验收报告返修时，派单及交付复用原问题编号或可定位条目，逐项说明处理范围及待确认或延期事项。普通小改按影响范围验证并检查最终差异。阶段报告写明已证明范围、版本与证据、未闭合项及负责人、下一动作和准入条件。会话状态和交付回报须与实际验收状态分开，阻断项闭合后才能放行。
