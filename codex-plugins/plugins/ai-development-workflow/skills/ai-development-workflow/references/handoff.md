# 接管与退出

仅在评估或执行会话接替、接管、归档时读取，同时按 [协作与交接](coordination.md) 核对职责、状态、授权和轮次出口；普通协作不必加载本引用。子 Agent 与独立主会话均适用职责、来源核验、产物保全和唯一写入权要求；绑定、读取历史、通知、恢复及归档按各自工具能力适用，不要求子 Agent 具备独立聊天生命周期。工具无归档能力时，核实停止相关写入、保全产物和证据并记录交接及退出状态即可，不虚报已归档；需要主动关闭或中止时仍核对操作授权，不以缺少归档功能代替停写确认。

以精简接管包承接长上下文：源会话/消息和继承链、最新决定覆盖关系、当前产物与有效证据、授权及限制、未结项/负责人/停止点、工作区/分支/HEAD/未提交状态、恢复步骤。包括执行者与用户直接交流形成的有效决定及来源、待答问题和实际同步状态；接替后沿用已核实决定及问题归属，不因换人重问或要求统筹重批，未送达或未采用的内容仍保留待同步。采用负责人串联时，接管包按[直接交接规则](direct-handoff.md)引用实际任务路线和执行记录，包括在途交接的实际证据、当前负责人、下一接手方、待核动作和终报收取入口。接替按现有切换规则核对这些信息。只读关键来源和受影响片段，摘要是索引而非授权原文的替代品。接管或迁移时，分别核对目录、Git 登记、分支与未提交状态、可用附件，并核对实际工作区、采用的绑定或显式目录定位方式及操作范围；缺附件不等于代码丢失，路径迁移不等于聊天已同步。

接管包中的技能版本须有可读取的正文、快照或可取回的提交；路径和内容指纹仅用于定位与识别，不能代替版本内容。旧路径已被覆盖时，先核对是否有可读取旧版本或用户更新的有效决定；用户已明确采用可访问新版时，依据新版及可核实的旧记录评估对职责、授权、在途任务及验证的影响，更新接管基线并同步受影响执行者，再按该版核验，无需找回已被该决定替代的旧版全文。无法核实的旧内容保留未知，不编造差异；影响接替判断的实质缺项仍须闭合。不得自行改用未确认版本；无法核对时保留缺项及恢复条件，仅阻塞依赖该缺项的接替或工作。

### 统筹接替流程

出现遗漏最新决定、混淆任务版本或负责人、反复重读相同材料且影响协调等具体迹象时，统筹主动提出接替建议，说明观察到的问题；不以聊天长度或一次正常上下文压缩直接触发切换。为清理上下文，优先建议新建精简会话，保留可核实来源；用户明确选择 fork 时尊重选择，并说明会携带旧历史。

创建接替会话、发送切换通知、变更回传对象和归档分别核对直接人类授权及来源，复用已有明确授权；技能规则、另一聊天的请求或接管包摘要本身不授予这些权限。工具或权限不足时交付人工接管包，只报告实际完成的步骤，不声称已切换。

1. **准备**：旧统筹整理上述精简接管包，补充本技能及所需引用的当前已确认版本和可访问入口（可用提交或内容指纹定位）、当前唯一统筹、拟接替对象、在途任务版本及执行者、已处理和未送达回报、相关检查点及续接方式。准备期间的新决定和回报继续由旧统筹处理，并保留增量，避免新统筹只接到过期快照。
2. **只读核验**：获授权后创建新统筹，任务包明确其暂不调度、不派业务任务。每一任新统筹必须读取并采用接管包所指已确认版本的本技能及所需引用，核对分工、授权和接替规则；技能不可访问或版本无法确认时列为实质缺项，不切换。接替后继续按本规则评估上下文退化，并在下一次接替任务包中传递同样的技能加载及后续传递要求，不因首次接替完成而失效。新统筹核验关键来源、最新决定、授权、任务状态和工作区，报告“可接管”或实质缺项。确认及切换前仍由旧统筹唯一负责；核验失败或新会话不可用时不切换，保留缺项和恢复条件。旧统筹无法参与时，按下述故障恢复规则处理，不由候选自行接权。
3. **明确切换点**：新统筹确认可接管后，旧统筹短暂停止新的业务派发，将准备期间增量补交，新统筹核对后，在双方可定位的现有权威记录中明确接替对象及生效的切换点。切换前旧统筹负责；切换生效后仅新统筹负责调度，旧统筹退出调度。新统筹核实切换已生效才开始派发；未能确认记录成功时保持待切换，先核查实际状态，不让双方同时调度，也不因缺少回执重复切换。

   正常切换前，在现有接管记录中核对下一检查点、在用定时检查和续接触发器的实际目标及状态、触发者和获准的读取入口，并确认关键回报在接替后有可行的收取路径。原触发器无法沿用时，明确由谁在何时唤起新统筹、先读哪个已核实可用的入口。关键回报仍无可行路径时，按现有接管规则列为实质缺项。旧统筹无法参与时，按故障恢复规则由用户指定新统筹及生效点，缺失路径仅阻塞依赖它的收取和后续衔接。接替沿用原检查点，切换期间已到期且未核查的事项交新统筹接续。

   切换生效后，新统筹核实触发器的实际状态。变更或停用须分别核对授权和操作结果，无法确认时记录旧触发器仍可能运行及其影响。定时检查或续接运行在调度、管理验收或写入当前协调状态前，须核实切换状态、当前唯一统筹及操作权限，无法核实时暂停这些动作。切换前已启动的运行同样适用。旧统筹仅延续获准的收件保全职责。对切换前已发出或可能生效的操作，新统筹先核查实际结果。结果未核实时，仅暂缓可能与旧操作冲突的写入或重试，以及依赖该结果的放行。独立且已获授权的工作继续。记录未知操作、受影响范围和恢复条件，待实际结果查明并处理，或核实相关后续动作与其无冲突后，再按原授权和暂停条件处理。故障接管同样适用。按现有规则去重，并分别记录收取路径缺口和待收取结果。

4. **更新回传**：按授权通知在用执行者当前唯一统筹及回传对象，仅更新协调关系，不重派、不打断执行中任务，不重置任务版本、业务授权或检查点。停止写入确认仅在产物执行负责人也发生变更时适用，不因统筹接替要求执行者停工。

   **授权复用与路径**：原授权不因统筹接替自动失效，主体、对象、事件及有效边界仍被覆盖的部分继续复用，不重复索权。固定向旧统筹C发送的授权不自动覆盖向新统筹D发送，也不自动将C安排为接替后的收件中转；新路径尚未明确时，保留待送的新结果，由D通过已有获授权的读取或人工转交收取，不按旧对象授权自行持续向C发送新结果，不重跑业务动作。切换前已发送或切换期间迟到的在途回报仍按下一步保全和收取。

   **旧统筹收件中转**：已有可核实的直接用户决定明确覆盖接替后继续向C收件、C的接收保全职责，以及D收取后续新增结果的方式和相应权限时，直接沿用该路径，无需重问或强制改成直报D。仅允许读取旧历史，不能推定允许读取切换后新增结果；C主动转发给D仍须相应消息授权。C仅承担获准的收件保全职责，不恢复调度或验收管理，也不因此获得持续监控、自动化或其他生命周期权限。工具不支持时保留摘要并采用已获准的可行兜底，不虚报送达或收取。

   **缺口收口**：切换生效后，由当前唯一顶层统筹D核查并选择可行回传路径，只补缺失的路径安排、对象变更、通知、转发或读取权限，不重复索取已覆盖授权，执行者不分别索权；明确决定选择中转后，原F→C发送授权仍有效且覆盖该路径的部分直接复用，不要求重新批准。无消息权限时保留待送或待授权摘要，采用人工转交或已获授权读取兜底。缺口仅阻塞相关回传及依赖它的衔接，其余独立且已授权工作继续；原职责、独立复验、用户接受、唯一写入权和暂停点不因路径变化而改变。

5. **失败与在途回报**：切换后的通知未送达或执行者尚未确认时，记录受影响对象，由新统筹在已有读取授权及其实际覆盖范围内读取旧会话和执行会话历史兜底；旧统筹不恢复业务派发。切换期间完成、阻塞或迟到的回报保留原任务版本、证据及已处理状态，由当前唯一统筹按既有去重规则收取，已验收结果不重复验收，待验收结果不当作已通过。缺少读取或消息能力时报告受影响的协调阻塞，保留待送达事项，不擅自恢复双统筹。
6. **退出**：新统筹确认已承接在途任务及回报，必要通知已送达，或失败通知已明确且新统筹核实可用的读取兜底，随后完成产物与工作树保全核对。统筹切换生效后，旧统筹退出调度。归档另行核验。即使已有归档授权，也须先确认执行存续、收件中转和结果收取对旧会话的依赖均已结束，或已有获准且核实可用的替代路径。归档核验须覆盖仍依赖旧会话的定时检查和续接触发器，包括关键回报的唤醒或收取路径，以及可能影响协调状态或证据保全的在途操作。上述依赖或影响仍未解决，或相关状态无法核实时，保留旧会话可访问，由当前唯一统筹处理缺口。已有获准且核实可用的替代路径，且旧触发器没有未解决的相关影响时，可按其他既有条件判断归档。触发器变更、停用和归档分别核对授权及实际结果。旧会话继续承担已获准的收件保全职责，原验收分工和暂停点继续有效。满足归档条件后，再按授权归档旧会话。兜底不可用或尚有指导职责时保留旧会话可访问，不为清理上下文提前归档。待送达事项保留在接管记录中，不重复成功回报。

### 旧统筹无法参与时

旧统筹不可访问或无法参与交接时，候选不得自行接权；由用户明确指定唯一新统筹及生效点，替代正常流程中依赖旧统筹确认和移交的环节。新统筹依据用户决定及已授权可读的记录、执行会话和现场核验基线、在途任务与实际状态；缺失接管包不要求旧统筹补交，缺失内容列待核项。未知状态仍记未知，不盲目重派、重跑或推定后台操作已停止；仅阻塞依赖缺失信息的任务。

用户指定及生效点须可定位，新统筹核实后按已确认范围调度；通知、回传和归档仍按正常流程及各自授权处理，指定接替不授权额外创建会话、停进程或其他写操作。原授权与暂停点继续有效；旧统筹恢复后不得自行恢复调度，应向当前唯一统筹交付未同步增量。

### 执行会话接替流程

执行会话出现遗漏要求、混淆版本、重复工作等影响执行的上下文退化迹象时，执行者沿已核实且获授权的回传链路报告，嵌套执行者默认先报原执行者，由其按授权转交当前统筹，或由统筹发现后提出接替；未设统筹时向用户报告。缺少直报统筹权限时不越级，链路不可用时沿用人工接管包或读取兜底。不单凭聊天长度轮换，也不先归档旧执行会话。创建接替会话、发送通知和归档仍分别核对直接人类授权；缺少权限或工具时交付人工任务包，不自行创建、迁移会话或扩大操作范围。

接管包同时传递执行者专业类别、任务涉及的项目及实际工作区、执行者类型、实际工作区定位方式及核验结果、默认目录与工具限制、主写项目及工作区/分支、产物归属，以及跨项目例外的用户授权来源、适用任务和有效边界。新执行者在同一任务中核验后延续有效例外，不重复索权；既有工作区及显式目录路线的适用授权可复用，但须重新核实当前目录、Git及现场状态，不因默认 cwd 不同要求迁移，也不把单次用户例外扩展到其他任务或会话；新增项目、职责或任务超出原范围时重新核对授权，不因接替扩大写入范围。后续每任接替继续传递这些边界，原暂停点和禁止动作仍有效。文档接替还须传递目标文档及可编辑范围、权威来源、最新正文版本、适用的操作前快照、已确认意见和待确认事项、唯一编辑者与专业内容负责人，以及未同步的用户修改和执行增量。新执行者核对最新正文，不以旧摘要覆盖后来的修改；仍按下述停写确认及唯一写入权流程接替，专业内容确认责任不随编辑者更换自动转移。

1. **保全现场**：复用精简接管包，明确任务版本、实际工作区/分支/HEAD、未提交及未跟踪产物、已有验证证据、当前进度、后台操作和未送达回报。分别记录未提交改动所在的工作区、分支及 HEAD，以及获准继续实施的目标工作区和分支、适用的归并安排及决定来源。两者不一致时，按[工作区定位](coordination.md#执行会话的工作区定位与操作范围)保全现场并核对搬移或继续实施所需的授权。移交产物和写入责任沿用已确认的分支安排。保留最新用户要求及其来源，尤其是暂停节点、禁止动作及恢复条件；不把未完成工作或待验收结果写成已完成。
2. **只读核验**：获授权后，新执行会话先读取已确认版本的本技能、任务适用技能及目标项目规则，核对任务、产物、证据和上述限制，并按协作引用核验工作区：独立主会话与子 Agent 均核对目标实际工作区、已采用的绑定或显式目录定位方式、Git状态、适用规则、读写范围及相关运行入口；跨项目任务分别核对各目标路径。默认目录不同本身不构成接替阻塞；依赖默认目标且不能正确选址的工具只限制相关操作，不自动创建、绑定或迁移聊天/工作树。核验不符按既有权限处理，未解决前不接管相关执行；暂不修改产物。缺少关键来源、技能或现场状态时报告实质缺项，保留原负责人，不自动接权。
3. **移交写入权**：确认旧执行者及相关后台操作已停止对交接产物写入，核对并补交最终增量、保全未提交产物后，由统筹（未设统筹时由用户）明确唯一新执行负责人及生效切换点，新执行者核实后才可继续写入。无法确认停写或切换生效时，新执行者仅只读核查，相关写任务保持待接管；独立且已授权的工作继续。此要求不授予杀进程、启停服务等额外权限。
4. **延续任务**：沿用原任务范围、有效版本、用户要求、授权限制、检查点及已核实的回传对象，不重复下发同一任务或从头重跑。已到用户暂停节点时保持暂停，不因换人恢复；可能已经生效的外部操作先核对实际状态。切换期间完成或迟到的回报保留证据和已处理状态，由当前统筹（未设统筹时由用户）按既有规则收取，不重复派修或验收。
5. **确认后退出**：新执行者确认接管后，统筹（未设统筹时由用户）核对产物保全、关联工作树清理及恢复影响，确认旧执行者无剩余执行或指导职责，再按工具能力和已有授权归档或记录退出。核验失败、停写无法确认或保全不足时保留旧会话可访问；旧执行者不可用也不构成其后台操作已停止的证据。
6. **后续接替**：每任新执行者继续适用本流程，在再次交接时传递相同的技能加载、用户边界和停写确认要求；不能将接替当作新建分支或worktree的授权。

未完成的接替步骤按既有轮次出口报告当前唯一负责人、缺项、下一动作及恢复条件；等待授权或核验不默认占用当前轮次，也不自行创建自动化。

归档按最新已确认的阶段范围和职责判断，阶段退出不以创建接替会话或指定后继执行者为前提。当前阶段仍需闭合的执行、复验、用户接受或指导职责，不能仅因 idle 或等待而视为完成；已明确延期、可独立重新安排的后续阶段，以及未来可能返修、复审的职责，不要求原会话常驻。

达到约定出口后，将后续未执行事项、有效证据、下一负责人或待安排状态、依赖及恢复条件保留在现有协调记录中，按工具能力及已有授权归档或记录退出；退出不表示项目全部完成、延期项通过或暂停解除。后来新增的独立任务不反向否定原阶段出口，也不默认由待归档会话承接。

归档前核对关联工作树类型、清理机制和恢复范围，保全仍需保留的产物及本地文件。Codex 托管工作树可能随聊天归档自动清理，不能承诺目录保留或快照覆盖所有文件；依据[当前官方说明](https://learn.chatgpt.com/docs/environments/git-worktrees)及实际工具核实，不由归档授权推定额外清理权限。拆开的制作、技术复验和用户接受职责分别保留状态，不能以制作交付推定全部完成。
