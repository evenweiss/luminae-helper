# 验证与阶段出口

用于专项取证、Mock、环境受限、提前独立验证、需求级测试、多方验收或切换发布。普通小改不必建立额外阶段。

## 最小补证

补充取证前，在现有记录中明确待证明结论、已有证据的具体不足及受影响范围，选择能区分实际行为的最小补证。优先复用已核源码、契约、样本和有效验证；索取完整镜像、构建归档或配置前说明其必要性及为何现有资料不足。局部缺证仅阻塞依赖该证据的结论和操作，其余可证明且已授权的工作继续，不把局部补资料升级为整项任务的门槛。

阶段结论写清：已证明范围、当前版本和证据、未闭合项及负责人、下一动作与准入条件。idle、turn 结束、代码交付或方案高分均不等于业务完成。若使用评分，只评价约定维度的方案成熟度；阻断未关闭不能靠总分放行，更不能据此声称软件正确。

## 环境受限时

分出本地/隔离可证明范围与需真实环境范围，分别给出通过条件；环境可用且获授权时正常验证，无需人为分两阶段。环境项延期附负责人、依赖和复工条件。涉及真机手势、跨账号交互或工具能力存疑时，正式验证前按需执行获准、无业务写入的最小检查，确认设备、账号角色、样本或操作工具能取得所需证据。能力不足时只挂起依赖它的断言，其他可验项继续。预检按实际覆盖记录。

Mock 和单测不能证明真实连通、鉴权链、配置生效、缓存/数据域或真实并发；Mock 浏览器实测仅证明已观察的 UI 和交互。前端 Mock、后端契约及适配层分别绑定所测版本，核对生产者和消费者样例；优先现有 schema、样例与测试工具，不新造框架。

## Mock 写入先证实隔离

运行可能写入的场景前，确认请求清单、目标、拦截范围、内存/本地消费者、未覆盖请求和导航。用可核实证据确认写动作被安全替身消费；未知动作、注入失败和配置错误应失败关闭，不能回落真实写接口。无法确认隔离时停止相关场景并报告，不靠“应该被拦截”继续。

壳层请求和跳转到真实页面单列边界；不要为验收越过已隔离区域。复用现有注入失败、延迟、乱序能力，缺失能力先明确修正范围和授权。检查请求目标、拦截结果、本地状态变化及相关失败路径，不以 Mock 文件存在代替运行证据。

确认实际加载版本及影响范围的未提交差异；不能仅凭 HEAD 推定运行的是当前源码，也不要为证据强迫提交。未确认版本的结论保留待补。启停服务由本次授权指定的人执行。Mock 交付附启用/退出方式、场景入口及影响复现的客户端状态（如 Cookie），并注明上述覆盖边界。

## 验收与证据

协作验收沿用项目已有记录并明确维护人。开发自验、专项独立验证、需求级独立验收和约定的用户业务/UI 接受分别核对，不以用户重测替代技术验证。

技术审查依据项目规则判断方案或代码风险。固定候选时按最终差异复核原审查范围，影响变化时只补受影响的审查，记录审查结论及适用候选。独立验收按实际行为和需求基线给出结论，另行记录。

验证按目的和责任划分，不按浏览器、接口等工具划分：

- 单个开发任务由开发者按改动范围自验，满足任务通过条件后交付候选版本、验证结果和未测项。有统筹时，由统筹核对证据及通过条件。前端包括浏览器中的展示、交互、请求及与设计稿对比；后端包括接口输入输出、错误处理及改动涉及的鉴权、归属和写入语义。按产物类型和风险选择验证方式；需浏览器实测或真实集成才能证明的行为，不能仅凭编译、静态检查或单测宣称通过。未测项说明原因及后续负责人。
- 满足项目约定的提测条件并进入需求级测试后，由未参与相关实现的验证者在独立上下文中验收，可复用合适的独立主会话或子 Agent。交接可定位的原始需求、设计或契约、已确认变更、候选版本和实际入口。验证者先据此确定预期，再参考开发自验报告，按风险验证关键业务路径、边界、真实集成和关联回归。开发仍承担自验。缺少验证者或派单授权时，保留自验及已完成的单任务交付，需求级验收记为待安排。
- 提前独立验证沿用用户、项目规则或已确认任务包中的明确要求。其他情况，只有能指出必须在需求级测试前作出的决定，以及需要独立判断的具体理由，才提出专项验证。普通覆盖缺口优先由开发补测。沿用已有授权安排，新增放行条件由用户或项目既定负责人确认。由未参与相关产物制作的验证者执行，复用任务包记录依据、范围、负责人和所影响的节点。缺少验证者或授权时，记录自验结果及专项待验证状态，仅暂缓已明确依赖该结论的动作。专项验证属于任务通过条件时，记录开发自验完成，任务待专项验证。
- 同一候选版本复用仍有效且可访问的证据。版本变化后核对原场景、入口及结论是否仍适用，保留仍适用的证据，只补受影响的验证。保留关键路径、争议项和证据缺口所需的独立实测。专项结论只覆盖该专项，需求级验收仍按完整需求范围给出结论。

每项验收点至少关联：基线来源、场景及可判断预期、执行者/版本、证据类型和实际结果、缺陷或延期及负责人。基线明确时，验证者独立判断实现是否符合。基线含糊或冲突时，记录分歧、影响和待确认项，由用户或项目既定负责人确认预期，再据此验证。预期明确的其他验收项可继续。

证据区分静态推断、隔离自动测试、真实浏览器/交互实测、真实集成、用户确认及未测。同一业务验收点可标部分验证，注明已证明和未证明部分；局部用例通过不能自动关闭整条。记录实际执行范围和结果，不合并不同版本或重复范围的历史测试数字。

决定性证据绑定工作区、加载产物、契约/Mock/场景版本、时间、预期和实际结果，以及 UI 所需 URL/浏览器；适用时以分支/HEAD及相关未提交差异指纹区分本地候选与已提交/推送版本，不能只凭远端 SHA 代表本地交付。敏感信息脱敏。

出口前核对证据可访问，将必要结论、失败/复验和截图保存在约定持久位置或可核实附件。临时目录只是暂存，不承诺长期可用；证据丢失仅补影响判断的范围。

缺陷优先回原负责人，否则明确接手人；修复后开发先自验，验证者按影响复验，标明旧证据失效范围及复验关系，仅补受影响证据，不默认重跑全部历史用例。区分新增缺陷、回归、旧已知问题、公共问题和待核项；豁免列范围、理由和批准人，不能算新实现通过。公共问题按所有权另列，不擅自扩修。

离线阶段按本阶段约定的覆盖与接受条件收口，隔离和证据须有效，阻断关闭，其他问题有处置，延期项有责任人与复工条件。写明“离线范围完成，集成未完成”，不以阶段完成代替整项目完成。

## Mock 清理和真实环境准入

满足约定的验收条件后，将本次临时 Mock 接入、注入或绕行机制的退出清理列为明确任务，先保全可恢复基线；长期回归所需的 Mock、场景和夹具按用途保留。获授权的本地清理与隔离回归可先做；移除 Mock 不授权真实写入，没有安全替身的写场景停止。真实旧接口回归、新接口接入和入口切换按环境准入执行。

等待结束或离线通过不构成自动复工许可。复工前核对环境可用及适用的暂停解除、具体操作授权、验证/发布责任人、目标代码和配置版本、生效机制、入口/流量状态、回归范围和豁免、恢复核对、观察窗口/指标及最终结项条件。未知项列待定，不能用旧环境记录冒充当前就绪。

配置内容吻合、实例已加载和真实连通分别取证；步骤依项目和平台确定，不硬编码技术栈或发布顺序。真实写测试事先说明目标、动作、影响、数据范围、快照及恢复/核对责任，获所需授权再执行。

切换前验证可恢复的“代码＋配置＋入口”组合，明确负责人、触发条件、顺序和观察；只写“可回滚”不足。保留并核对上线期间合法新写入，不默认用旧快照覆盖。恢复数据也按写入授权执行。满足约定观察和结项条件后才报告最终完成；旧路径下线另行决策。
